New package: the catalog's saved queries, dashboards, saved-query revisions, audit trail and curation overlay on Drizzle and PostgreSQL, for hosts that do not run MikroORM. `DrizzleWorkspaceStore` implements `CatalogWorkspaceStore` and `DrizzleCatalogOverlayStore` implements `CatalogOverlayStore`. Each takes either a Drizzle database or a `run` function that executes work in the host's own transaction. Table names take a prefix (default `catalog_`, matching the MikroORM store) and an optional schema. The tables ship as Drizzle definitions for drizzle-kit and as SQL (`catalogDrizzleSql()`, `sql/catalog.sql`) that needs no superuser. Column types, precisions, defaults and index names match what the MikroORM store creates on Postgres, so a database it already set up needs no migration. `run` must give each call one transaction or savepoint; `recordEvent` writes in a savepoint of its own, so a failed audit insert never aborts the host's transaction.
